V41 工作台测试合集

入口（在 comic 目录执行）：
  npm run test:small              小改动：核心功能 + 核心链路
  npm run test:large              大改动：全量功能 + 全量链路，重复文件只执行一次
  npm run test:core-functions     核心功能
  npm run test:all-functions      全量已发现自动化功能测试
  npm run test:core-flows         核心工作链路
  npm run test:all-flows          全量已登记链路测试

也可双击本目录对应的 .cmd。要求 Node 24，依赖沿用本机已安装运行环境。

命令参数：
  node quality/run.mjs --suite small --list
  node quality/run.mjs --suite large --jobs 1 --timeout 150
  node quality/run.mjs --suite core-flows --filter core-user-flow
  node quality/run.mjs --suite small --output D:/本次测试结果
  --filter 仅用于定位单项，不能将过滤运行称为完整套件通过。

结果：verification/quality-runs/<时间>/report.html、results.json、results.csv、inventory.json 和逐文件日志。
完成后退出码 0 才表示所选套件全部通过。失败、超时、安全阻断、跳过任一存在则退出码 1。
--list 不执行测试，不可用它宣称通过。全量按运行时实际发现文件，不固定旧测试数量。

运行边界：
每次复制独立源码，排除用户数据、账号、本地会话、运行数据库和凭据；不修改使用中的工作台工程。
测试使用合成 HOME/CODEX_HOME、本地服务、普通合成账号和假生图通道。
禁止访问外网/生产墨库及高权限/真实生成CLI；触发后登记 blocked，不能算通过。
默认逐文件串行；--jobs 可设1到4，但旧测试共享固定端口/证据路径时建议保持1。
生成质量、真实付费通道、生产负载、跨机团队发布、墨库正式V版本统一不在隔离自动化通过结论内。
全量仅代表全部已发现测试，不等于所有用户功能均已有测试。coverage.json 单列未建立专项测试的功能。
旧脚本失效和产品失败都保留日志，不能删除测试或修改业务期望让结果虚假通过。

改动范围自动建议：npm run test:changed -- --dry-run；不带 --dry-run 则执行建议套件。仅少量展示/文档变更采用核心，后端、协议、数据或无法判断范围一律采用全量。人工判断风险更高时应直接运行 test:large。
Python test_*.py 也纳入全量，并使用隔离测试启动器；模型缺失及被移除的旧worker仍记为失败/阻断，不静默略过。

默认 npm test 运行小改动套件。原始混合测试入口保留为 npm run test:legacy；所有原始测试仍被全量入口动态发现，不因移到核心外而删除。
