# 主版本发布与升级

主版本可在团队成员列表的“版本发布”列授予或撤销发布权限。授权同事可从自己的工作台预览并发布本机代码，新版由主版本签名，主机与同事均通过安全升级安装。只有主版本管理员能改变权限。详见 [版本发布权限说明](distribution/版本发布权限说明.md)。

发布服务以实际启动目录为代码根目录。同事完整包不含主版本私钥，每台电脑独立保留自己的工程和账号。

## 主机如何发布

主版本电脑双击“启动工作台.cmd”即可同时启动编辑器、资产工作室、本机执行器和团队发布服务。启动器通过仅存于主机的签名身份识别主版本；同事包只连接主机，不会建立第二个团队中心。“启动主版本发布.cmd”仍可单独启动发布服务。发布服务观察当前目录的代码；连续扫描稳定并通过 JavaScript 语法检查后，生成签名版本，保留历史发布包。首次发布包含完整代码，之后同事按文件摘要识别变化；即使跳过中间版本，也能正确清理自己旧版登记的已删除代码。

主版本页面默认在 `http://127.0.0.1:18914/`。在 Codex 更新代码时保持该服务运行；无需逐个复制文件给同事。签名私钥只放主机的 `runtime-data/distribution/master/`，不进入同事包。只有本机可请求立即发布。

优先复用主版本漫画工具已经连接的画格协作中控；从主版本自己的本机配置读取配对权限，权限不进入代码包。保存的中控地址指向本机且自有中控状态仍存在时，停止的中控可按原身份恢复；远程中控离线不会新建替代中控。尚无中控且 18897 空闲时才创建新中控，不建立重叠监听。主机漫画工具尚未配置中控时会自动配对。项目中心仍使用当前 8790 服务，接单器的读/提交权限由主机按允许项目独立签发。项目中心暂时离线时，团队会话和版本服务仍会启动；新同事接入项目仍需项目中心恢复后完成。

## 同事如何升级

同事启动工具后自动检查和下载签名升级包，编辑器顶部显示“收到新版 · 升级”。点击进入版本管理，再点击“安全升级并重启”，会：检查所有受管服务及接单任务是否空闲；正常关闭本套工具；备份会变动的旧代码；核验主版本签名、文件长度和 SHA-256；替换代码；重启本套工具。

升级按每台电脑独立执行。主机点击“一键升级所有同事”后，空闲电脑先升级；正在生图或状态待确认的电脑继续原任务，结束后每15秒自动复查并升级，不阻塞其他同事。本机手动点击升级遇到忙碌时也会记住安排，空闲后继续。旧版强停接收器不接收此指令，需先在该电脑正常升级一次以启用新版接收器。主机发布服务自身重启仍核对其承载的协作任务，这不妨碍向同事派送更新。脚本不按端口强杀别的程序，不替换其他安装目录。人工改动的本机代码默认阻止覆盖；应先导出差异，合并回主版本。

主机每次升级前，把完整源代码备份到 `runtime-data/distribution/source-backups/`。每份包含 `snapshot.json` 文件摘要和 `files/` 源码目录，保留最近 5 个源版本；升级成功后自动删除更早的版本。主机身份以本机主版本签名配置识别，同事电脑不保留源码备份。

替换过程在 `runtime-data/distribution/backups/` 临时保存本次会被修改的文件，用于故障自动还原；升级成功后清掉这些临时副本，同事电脑不因此积累旧代码。下载包与主版本发布包各最多保留 3 份，已淘汰的登记代码文件和空目录按清单移除；未登记文件和含人工内容的备份保留并提示。工程、图片、账号、模型和字体不参与清理。

文件替换中途失败会自动恢复旧代码。需要人工回退时，先正常停止本套工具，再由 Codex 校验主机源码备份的摘要并还原；同事从团队升级频道取回指定版本，不依赖本机历史备份。

升级页会显示具体阻塞任务：执行人、作品、资产或画格、进度、最近回传时间和下一步。状态回传中断时显示“执行状态待核实”，保留原任务；不得清空占用或重复提交生成来绕过升级保护。

## 分发范围

包含漫画编辑、同页修图、资产工作室、生成执行器、项目中心、协作协议、运行器、安装升级代码及开发测试。账号、真实工程、参考图、生成图片、资料原件、处理结果、日志、缓存和机器配置不进入共享代码包。大体积模型、运行环境和字体继续从墨库固定版本恢复；后续升级不重复下载已校验的环境。

当前发布频道绑定主机局域网地址和主版本公钥。主机 IP 发生改变时，在主版本重新生成频道并重新交付接入信息；不要让同事自行信任陌生来源的升级包。更换公钥需要重新分发可信代码包，不能由网络下载的清单自动更换信任锚点。

Windows 防火墙需允许主机在私有网络上向同事提供 8790（项目中心）、18897（画格中控）、18914（代码与环境发布）。同事的编辑器和版本管理默认仅监听回环。发布服务不会调整系统代理，不会复制主机 Codex 或墨库凭据。

真正的代码功能质量仍需主版本开发时验证。自动发布的语法检查不是视觉验收；升级完成也不代表已替同事登录或已生成图片。

## 团队状态与快捷入口

编辑器顶部提供“排版 / 修图”“墨库”“项目中心”和“团队 · N 在线”。点击团队或“更多 → 版本更新 / 团队接入”，可查看成员、电脑名称、在线状态、所用版本、当前项目/画板与任务。主版本发布服务首页也是完整状态页面，不显示调试 JSON。

同事通过“启动全部.cmd”启动后，每15秒向主版本上报设备状态；浏览器每10秒向自己的本机服务登记当前画板与编辑模式。生成执行器中的正在生成或排队资产也会显示。90秒没有收到设备心跳后显示离线，离线项目是最后上报的信息。关闭画板后不把历史工程当成当前项目。旧客户端没有这套上报能力时标记“未上报”，需先升级并重新启动。

姓名优先使用保存的个人身份或本人墨库显示名；缺少姓名时提示补全，电脑编号仅作为次要设备信息。主版本可以直接修改成员姓名。只上报项目名称、画板名称和任务简况，不传账号、工程正文或图片。主版本页面可立即检查并发布，同事页面链接自己的本机安全升级页。

顶部“会话”提供团队会话、私聊、项目群聊、文件传输和对方确认后的工具页面远程协助。详见 [协作会话与远程协助](distribution/协作会话与远程协助.md)。会话与传输文件保存在主版本的运行数据中，不包含在升级代码里。


封面、尾图新增本地上传和 Ctrl+V 粘贴；原生 imagegen 附图超过5张时自动生成带标签的参考拼图，保留原件与全部对应记录。具体见 [封面尾图与参考合图说明](distribution/封面尾图与参考合图说明.md)。

## 主机一键强制升级同事

在主机“团队与版本”页点击“一键强制升级全部同事”。指令按登记的电脑逐台执行，不包含主机自身：核验主机签名及代码包，停止本套工具的本机任务，保存取消记录，替换代码、清理淘汰文件并重启。已是目标版本的电脑直接回报。工程、原图、账号、模型和字体保留；同事端不保留旧源码备份。未保存的页面编辑可能丢失；云端已提交的任务保留原编号，不自动重新生成。

升级结果必须以重启后的真实版本回传为准。进度区显示等待接收、下载校验、停止任务、替换代码、重启、完成及失败。离线电脑启动工具后接收待执行指令。旧版没有指令接收器，需要先在该电脑完成一次普通升级并重启，之后即可由主机统一操作；旧版不会被显示为升级成功。普通“安全升级并重启”继续保留任务空闲和本机代码差异保护。
