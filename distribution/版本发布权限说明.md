# 版本发布权限

主版本管理员打开“团队与版本”，在成员列表的“版本发布”列点击“允许发布新版”。授权绑定该成员的已登记设备，修改姓名不会清除权限；另一台设备需要单独授权。点击“撤销发布权限”立即禁止该设备继续提交新版。只有主版本管理员能改变权限，被授权的同事不能给其他人授权。

同事先升级到包含此功能的版本，再从自己的工作台打开团队页面。获得权限后，会显示“发布本机新版”。点击后查看新增、修改、删除的代码文件，填写更新说明，然后确认发布。预览后代码又发生变化时，需要重新预览。

发布只提交白名单内的工具代码。工程、账号、素材、模型和缓存不会上传。频道地址、公钥及固定环境清单由主版本维护，同事不能通过发布请求覆盖这些配置。主版本私钥始终保留在主机。

团队中心检查设备身份、权限、基线版本、路径、文件大小和 JavaScript 语法，再签名并分发。同一天版本号递增。发布结果附带发布人和更新说明。授权、撤销及发布记录保存在主版本运行数据中。

新版发布成功后，主版本电脑与其他同事都通过“安全升级并重启”接收。发布不会热替换主版本正在运行的代码或打断生成任务。主版本自动扫描不会将尚未安装的同事版本回退；主版本后续修改按文件合并，同文件发生冲突时会停止发布并要求合并。两位同事同时基于旧版本发布时，仅第一份能成为新版，另一份需保留改动并同步、合并后重新发布。

发布请求使用固定编号。发送后连接中断，可在原窗口重试，服务端返回原发布结果，不重复新增版本。撤销权限后，服务端仍会拦截请求，即使旧页面上还显示发布按钮。
