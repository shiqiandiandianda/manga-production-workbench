## 4. 第一阶段：中控协议级故障注入（9/9 通过 ×3）

### 4.1 执行方式

### 4.2 场景与结果

## 5. 第二阶段：端到端多进程模拟（10/10 通过 ×3）

### 5.1 进程拓扑（真实执行）

```
┌─────────────────────────── 测试进程（node:test，包内 node v24.19.0）───────────────────────────┐
│  · 假生图通道 HTTP 服务（fake-comic.mjs，随机端口，合成 PNG + 真实 sha256，可注入挂起/故障）      │
│  · A 端真实漫画服务：createStudio(fake 生图桥) + listen(0)  ← 真实 /api/collab/* 路由与自动回填   │
│  · B 执行层真实漫画服务：createStudio(fake 生图桥) + listen(0) ← 真实 collab-jobs/pump/名额      │
│  · 节点→中控 故障注入代理（真实 HTTP 转发；可对结果上传注入一次 500）                            │
└───────────────┬──────────────────────────────┬──────────────────────────────────────────────┘
                │ 真实 HTTP（x-collab-token）    │ 真实 HTTP
   ┌────────────▼─────────┐        ┌─────────────▼──────────────┐
   │ 中控子进程            │        │ 节点甲子进程 节点乙子进程     │
   │ 中控.mjs --port 随机  │◄──────►│ 节点.mjs run --config        │
   │ --data 临时 dataDir   │ 心跳/派单│ 独立 dataDir/名字/token      │
   │ 小 leaseMs=2000       │ 结果上传│ journal 落盘；甲→假生图通道   │
   │ heartbeatTimeout=1500 │        │ 乙→B 执行层真实漫画服务       │
   └──────────────────────┘        └──────────────────────────────┘
```

- **真实子进程**：中控 1 个 + 节点 2 个（`开发/协作/中控.mjs`、`开发/协作/节点.mjs run --config`），随机端口/临时 dataDir/小 `leaseMs`/`heartbeatTimeoutMs`，节点日志与 journal 真实落盘。
- **真实服务代码**：A 端与 B 执行层均为进程内真实 `createStudio`（真实 HTTP 路由、Store、pump、名额、collab-jobs、collab-client、collab-apply），按 Lead 确认的「进程内起服务 + 真实 HTTP」方案（非独立 OS 进程）。
- **模拟部分（明确非真实）**：生图桥是 fake bridge（返回合成的合法 PNG，绝不联网）；节点甲的 localComic 指向测试自带「假漫画服务」（协议级替身，返回真实合成 PNG 文件 + sha256）；节点→中控结果上传经过测试代理以注入一次 500。
- A 端自动回填：`dataDir/collab/client-config.json`（hubUrl/token/clientId/enabled=true/autoApply=true/pollMs=500），走真实后台轮询。

## 6. 发现的问题与处理状态

| 编号 | 发现阶段 | 严重度 | 问题 | 处理状态 |
|---|---|---|---|---|
| #1 | 第一阶段 | 低（页面/自动回填均显式传 limit，暂未影响 UI） | `GET /api/tasks`、`GET /api/assets` 不传 limit 时只返回 1 条（total 正确）：hub-server 把缺省 `null` 传给 `clampInteger`，`Number(null)=0` 被收敛为 1，fallback=100 失效 | **已修复并复跑通过**：hub-core 增加 `optionalValue` 处理（tasks/assets/notifications/节点设置），并补回归；本验证 9/9 含缺省 limit 回归，3/3 稳定 |
| #2 | 第二阶段 | 低（不重复建任务、数据未损坏；属幂等语义/UX） | 回填完成后再次提交同一画格 → 中控 409 `idempotency_conflict`（A 端 distribute 返回 tasks=[] + errors）：A 端幂等键只含 panelContentKey 前16+referenceKey 前8，而 hub payloadHash 含 `target.expected`（回填改变 imageAssetId → geometryKey 变化） | **已修复并复跑通过**：Lead 决策方向 A —— 幂等键改为 `projectId:panelId:sha256(panelContentKey\n geometryKey\n referenceKey\n revision).slice(0,16)`；未回填连点仍 duplicate，回填后再次提交=新任务；保留 409 兜底（旧任务时回落 duplicate）。本验证 10/10 含该回归，3/3 稳定 |

> 说明：验证过程中出现过的失败均为**测试自身时序/清理问题**（e2e 首版场景失败后残留节点子进程、claimed 场景杀节点过早），已修复在测试侧，不涉及实现缺陷；最终版本 3/3 稳定、无孤儿进程。
