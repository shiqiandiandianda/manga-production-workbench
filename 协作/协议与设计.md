# 局域网中控 + 多电脑协同生图 + 共享资产 —— 协议与设计（v1.0.0）

本文件是实现的唯一契约。中控（hub）、节点（node）、漫画服务接入层、控制台页面、测试都按本文件实现；
改接口/状态机必须同时改本文件与 `lib/protocol.mjs`，并补测试。

## 0. 范围与原则

- 只复用现有桌面端生图链路：节点调用**本机漫画服务**（`开发/comic`，默认 `http://127.0.0.1:18896`）现有的
  `CodexBridge` / `JimengBridge` + `pump()` 名额调度，不直连任何生图 API、不新增付费通道、不模拟生图。
- 协作任务与个人任务分目录、分记录：协作任务在漫画服务里是 `kind:'collab-generation'` 的独立 job，
  工作目录 `dataDir/collab/jobs/<jobId>`，不会混入同事正在编辑的工程任务列表。
- 小团队可安装：全部 Node 内置模块，**零 npm 依赖**；沿用包内 `开发/workbench/运行环境/node/node.exe`。
- 不破坏现有流程：现有 4328/18896/4329/7878 端口、接口、编辑器行为保持不变；新能力走新文件/新路由。
- 旧执行尝试的迟到结果只登记、不覆盖新尝试；回填只做一次；回填前校验目标编辑版本。

## 4. 中控 HTTP API（默认 `http://<中控IP>:18897`）

鉴权：`x-collab-token: <token>` 或 `Authorization: Bearer <token>`；`GET /api/health`、`POST /api/pair` 不需要。
图片类 GET（`/api/blobs/...`）额外允许 `?token=<token>`（浏览器 `<img>` 无法带头）。
错误统一 `{ "error": "中文原因", "code": "machine_code" }`，HTTP 状态 400/401/403/404/409/413/429/500。

### 4.1 公共
- `GET /api/health` → `{application:"photocraft-collab-hub", version, protocolVersion, hubId, hubName, codeRoot, dataRoot, time, pairingRequired, nodes:{total,online}, tasks:{queued,running,uploading,verifying,done,failed}, assets:{total}}`
- `POST /api/pair` `{pairingCode, role:"node"|"client", name, platform?, version?}` →
  `{clientId, nodeId|null, token, role, hubId, hubName, protocolVersion}`；配对码错 401。node 角色同时创建 nodes 记录。

```jsonc
                "hasResult": false, "likelyGenerated": false }] }
```

- `POST /api/node/tasks/:taskId/progress` `{attempt, phase:"generating"|"uploading", message?}` → `{ok:true}`

  `result_available` 后再走 result 上传；`no_result` → 任务 failed；`still_running` → 保持 verifying 并续租。

### 4.3 客户端（role=client，节点 token 也可读）
- `PUT /api/blobs` 原始图片字节；头 `x-sha256`、`content-type` → `{sha256, blobId, size, mime, width, height, deduped}`（同内容幂等）。
- `GET /api/blobs/:sha256` / `GET /api/blobs/:sha256/thumb` → 原图 / 缩略图字节（thumb 不可用时 404，客户端回退原图）。
- `POST /api/tasks` 建任务：
```jsonc
{ "idempotencyKey": "<projectId>:<panelId>:<目标指纹16位hex>（A 端 collab-client 生成，见下）",
  "type": "panel-generation",
  "projectId": "...", "projectName": "...", "episode": 21, "panelCode": "E21-003", "panelId": "...", "shotCode": "...",
  "prompt": "...", "style": "...", "size": {"w":1280,"h":900},
  "target": { }, "generationInput": { },
  "references": [{ "sha256": "...", "role": "character", "name": "叶麟", "mime": "image/png", "size": 123 }],
  "submittedBy": "client_<uuid>" }
```
  → `201 {task}`；`idempotencyKey` 已存在且 payloadHash 相同 → `200 {task, duplicate:true}`；不同 → `409`。
  **A 端幂等键（实现定稿）**：`projectId:panelId:sha256([panelContentKey, geometryKey, referenceKey, String(revision)].join('\n')).slice(0,16)`。
  这样「未回填时连点两次」同键=duplicate 不重复建任务；「回填成功后再提交」因 `geometryKey`（含 imageAssetId/imageTransform）变化得到新键=重新生成；
  改提示词/参考/画格/保存版本同样得到新键。中控仍按 payloadHash 校验，A 端保留 409 兜底（分页找回同键旧任务返回 duplicate）。
- `GET /api/tasks?projectId=&submittedBy=&status=&applyStatus=&since=&limit=&include=input` → `{tasks:[...], total}`
- `GET /api/tasks/:taskId` → `{task}`（含 generationInput）
- `POST /api/tasks/:taskId/cancel` → 未完成可取消；已完成 409。
- `POST /api/tasks/:taskId/retry` `{reason?}` → 仅 failed/verifying/cancelled 可重派；`attempt+1`，状态回 `queued`，保留历史尝试与迟到结果。
  （`protocol.mjs` 迁移表已允许 `verifying → queued`；资产生成任务完成后中控置 `apply.status='skipped'`，表示无需回填画格。）
- `POST /api/tasks/:taskId/apply` `{status:"applied|conflict|candidate|failed|skipped", detail, by}` → 幂等：已是同一状态返回 `{duplicate:true}`；只有 `pending` 可迁移。
- `GET /api/assets?projectId=&q=&kind=&status=&allVersions=&limit=&offset=` → `{assets:[...], total, lastSeq?}`
- `GET /api/assets/:assetId` → `{asset, versions:[...]}`（同 lineage 全部版本，新→旧）
- `POST /api/assets/request`：
```jsonc
{ "projectId": "...", "kind": "character", "name": "叶麟", "form": "道袍", "costume": "太玄预备杂役道袍",
  "style": "国漫", "forceNewVersion": false,
  "prompt": "...", "size": {"w": 1024, "h": 1024},
```

  → `{mode:"reuse", asset}`（已有 available 版本，直接复用）

  / `{mode:"create", asset, request, task}`（本次新建 pending 资产 + 排队任务）。
  查重键 = `normalizeAssetKey({projectId,kind,name,form,costume,style})`；**只看语义字段，不看文件名**；form/costume/style 任一不同都不合并。

## 5. 任务生命周期与可靠性规则（中控必须逐条实现）

状态：`queued → running → uploading → done`，另有 `failed / verifying / cancelled`。`phase` 同步显示细阶段。
尝试（attempt）：每次派单 `attempt+1`，旧尝试永久保留。

1. **排他领取**：`heartbeat` 中派单在一次事件循环内完成检查+写入（Node 单线程，检查与置位之间不得 `await`），同一任务绝不派给两个节点。
2. **名额**：节点上报 `freeSlots = min(设置上限-本机协作在跑数, 本机漫画服务空闲名额)`；中控本轮最多派 `freeSlots` 个；`paused/enabled=false` 不派单。
3. **心跳与租约**：节点每 3s 心跳；中控 `leaseMs=120s` 续租。`lastSeenAt` 超过 `heartbeatTimeoutMs(15s)` → 节点标记离线并通知；超过租约未续：
   - 尝试仍 `claimed`（未开始生成）→ 任务回 `queued`，尝试 `abandoned`，可重派；
   - 尝试已 `generating` → 任务 `verifying`，尝试 `unknown`，**不得自动重派**。
4. **断线恢复**：节点重启后把 `journal` 随心跳上报，中控给裁决：
   `keep`（任务仍归此尝试，继续查本机 job）/ `verify`（需核实生成结果）/ `retry_upload`（图已生成、上传失败，优先重传）/
   `late`（已被新尝试接管：旧结果只登记 `lateResults`，不覆盖）/ `done` / `abandoned`。
5. **生成失败与上传失败分开**：生成失败 → `failed`（可重试）；上传失败 → 尝试 `upload_failed`，任务保持 `uploading`，节点退避重传（已有图片优先重传，不重新生成）；连续失败超阈值才转 `verifying` 并等人工核实。
6. **重复回传**：同一尝试、同一 sha256 → `{duplicate:true}`，不重复登记、不重复回填。
7. **旧结果迟到**：尝试号 ≠ `activeAttempt` 或任务已完成但 sha 不同 → 写入 `lateResults` + 通知，**不覆盖**当前结果、不触发回填。
8. **校验后完成**：只有通过 sha256 + 图片头/像素尺寸校验的结果才能把任务置 `done`；坏文件返回 400，任务保持原状态。
9. **中控重启恢复**：启动时重读 state：过期租约按第 3 条处理；`uploading` 且无结果 → 保持并等待节点重传；
   已完成但 `apply=pending` 的原样保留（A 端会继续回填）。已配对节点 token、任务、资产全部保留。
10. **回填只一次**：任务 `apply` 从 `pending` 迁移一次；A 端另用本地 `apply-journal` 防崩溃重复回填。
11. **共享资产并发申请**：`POST /api/assets/request` 的「查重 → 复用/关联/新建」在同一事件循环内完成，并发申请同一 dedupeKey 只会产生一个 pending 资产 + 一个任务；结果回来时同一事务内把 pending 资产置 available 并把请求置 done。

## 6. 节点代理（`节点.mjs`）

配置 `config/node.example.json`（字段含义）：
```jsonc
{ "hubUrl": "http://192.168.1.10:18897", "token": "<配对得到的 token>", "nodeName": "B电脑-小明",
  "dataDir": "../../运行数据/协作/节点-小明",
  "localComic": { "origin": "http://127.0.0.1:18896", "provider": "codex" },
  "maxConcurrency": 2, "enabled": true, "paused": false,
  "allowedProjectIds": [],            // 空=不限制；非空时只执行这些项目
  "allowedTaskTypes": ["panel-generation", "asset-generation"],
  "heartbeatMs": 3000, "pollMs": 1200, "uploadRetries": 6,
  "taskTimeoutMs": 1800000 }
```
流程：配对 → 心跳循环（带 journal/名额）→ 对每个 assignment：
1) 写 journal（`claimed`→`submitting`）→ 2) 下载参考图到 `tasks/<taskId>/<attempt>/refs/`
3) `POST {localComic.origin}/api/collab/generation`（§7）得 `jobId`，journal `submitted`
4) 轮询 `GET /api/collab/generation/:jobId`（1.2s）上报 `generating` 进度
5) 完成：校验结果文件（存在、可读、sha256、像素），journal `result_ready`；`PUT /api/node/tasks/:id/result` 上传，失败退避重传（最多 `uploadRetries` 次），成功 journal `done`
6) 本机任务失败：若曾进入 `generating`（或任务有 `generationStartedAt`）→ 上报 `likelyGenerated:true`；否则 `false`
7) 启动恢复：加载 journal 对每个未完成项按中控裁决继续（见 §5.4）；`upload_failed` 优先重传；`submitting` 视为可能已生成
8) 不执行任意命令：只访问上述固定接口 + 白名单任务类型/项目；任务里的 prompt/参考名只当数据，绝不拼命令行。

## 7. 漫画服务执行适配层（A/B 两端同一套，端口 18896 回环）

### 7.1 节点侧（B 执行）
- `POST /api/collab/generation`：
```jsonc
{ "taskId": "task_...", "attempt": 1, "provider": "codex",
  "generationInput": { },   // A 端 prepare 产出的、与本地 /api/jobs input 同构的结构
  "referenceFiles": [{ "role": "character", "name": "叶麟", "filePath": "C:\\...\\refs\\1-叶麟.png" }] }
```
  行为：校验自包含输入 → 登记参考图为本地 asset（不改动用户工程）→ 建 `kind:'collab-generation'` job 入现有队列
  （共享 `pump()`、`generationSlots`、Codex/Jimeng 桥）→ 返回 `202 {jobId}`。
- `GET /api/collab/generation/:jobId` → `{jobId, status:"queued|running|done|failed|cancelled", phase, message, progress,
  result:{filePath, sha256, size, mime, width, height, assetId}|null, error:null, startedAt, completedAt}`。
- `POST /api/collab/generation/:jobId/cancel` → `{ok:true}`。
- 结果落在 `dataDir/collab/jobs/<jobId>/`，与用户工程任务目录分离；完成后 job 保留 24h 供节点重传/查询。

### 7.2 A 端提交与回填
- `POST /api/collab/prepare` `{projectId, panelIds:[...]}` → 逐个画格返回：
  `{panelId, panelCode, shotCode, prompt, style, size, target:{...}, generationInput, references:[{role,name,assetId,filePath,sha256,size,mime}]}`。
  `generationInput` 必须与现有 `POST /api/jobs` 为同一画格组装的 input 完全一致（同样的 shot/panel/style/referenceRoles），
  保证换电脑跑出来的提示词/参考顺序一致。`target.expected` 记录：
  `{revision, panelContentKey, geometryKey, referenceKey, generationToken}`。
- `GET /api/collab/config` / `PUT /api/collab/config` `{hubUrl, token, clientId?, clientName?, enabled, autoApply}`
  → 保存到 `运行数据/协作/客户端.json`；`GET` 不回传完整 token（只回 `tokenSet:true`）。
- `POST /api/collab/pair` `{hubUrl, pairingCode, clientName}` → 调中控 `/api/pair` role=client，保存 token/clientId。
- `POST /api/collab/distribute` `{projectId, panelIds:[...]}` → prepare → 上传参考图 blob → 建中控任务；
  返回 `{tasks:[{taskId, panelId, panelCode, duplicate}], errors:[{panelId,error}]}`。
  幂等键 = `projectId:panelId:sha256(panelContentKey\n geometryKey\n referenceKey\n revision).slice(0,16)`（见 §4.3）：
  未回填时重复点不重复建任务，回填后再点=重新生成；参考图按 sha256 只上传一次。
- `GET /api/collab/status` → `{configured, hubReachable, hub, client, autoApply, pendingApply, lastSyncAt, lastError}`
- `GET /api/collab/tasks` / `GET /api/collab/tasks/:id` / `POST /api/collab/tasks/:id/retry` / `cancel` → 代理中控。
- `GET /api/collab/tasks/:id/result` → 结果图片预览字节（A 端从本机中控下载缓存后返回；任务列表项可带 `previewUrl`）。
- `GET /api/collab/nodes` → 透传中控节点列表（节点名展示可选；页面不强制使用）。
- `POST /api/collab/tasks/:id/apply-choice` `{choice:"force|"candidate|"discard"}` → 处理回填冲突（见 §8.2）。
- `GET /api/collab/assets?...`、`GET /api/collab/assets/:id`、`GET /api/collab/assets/:id/thumb`（代理字节）、
  `GET /api/collab/assets/:id/download`（按需下载原图到本地缓存并登记为本地 asset → `{assetId, filePath, name}`）。
- `GET /api/collab/notifications?since=` / `POST /api/collab/notifications/read`（代理 + 本地回填事件合并）。
- `POST /api/collab/assets/request` → 代理中控资产申请（先本地 prepare 资产生成 input，见实现约定）。

### 7.3 自动回填（A 端后台循环，默认 3s）
命中条件：`status==='done' && apply.status==='pending' && submittedBy===本机 clientId`。
1) 下载结果 blob 到本地缓存 `运行数据/协作/结果/<sha256>.png`（校验 sha256）
2) `applyCollabResult`：重新读取工程/画格，比较 `target.expected` 与当前值（§8）
3) 成功 → 本地登记 asset、写入画格、`POST /api/tasks/:id/apply {status:'applied'}`
4) 冲突 → 结果保留为画格候选 + 本地通知、`POST apply {status:'conflict'}`；页面提供强制/仅候选/丢弃
5) 崩溃安全：本地 `apply-journal.json` 先写「applying」再改画格，成功写「applied」；重启后已 applied 的不再重复。

## 8. 回填规则（必须防覆盖）

### 8.1 版本校验
回填前比较当前值与 `target.expected`：
- `project.revision`（编辑保存版本）
- `panelContentKey`（提示词/参考/画风/机位等语义）
- `geometryKey`（格子 x/y/w/h/points/imageAssetId/imageTransform）
- `referenceKey`（参考绑定）
任一不同 → **冲突**：不覆盖 `imageAssetId`，把结果加入 `panel.candidates`，保留图片与记录，通知 A 端用户选择。
`force` 仅由用户点击「仍然应用」触发。`candidate` 模式只入候选、不动当前画面。
（原有正常生图流程逻辑不变；本规则只作用于协作回填。）

### 8.2 冲突处理
`POST /api/collab/tasks/:id/apply-choice`：
- `force`：用户确认后按当前画格写入，同时保留候选；中控 apply=applied（detail 记录 force）。
- `candidate`：只入候选，中控 apply=candidate；画格当前画面不变。
- `discard`：中控 apply=skipped，本地不写入（结果仍在资产/中控）。
所有选择幂等；已 applied 的不再改。

## 9. 共享资产

- 索引字段：唯一编号（assetId）、lineageId、版本、项目、角色/道具/场景名、形态 form、服装 costume、画风 style、来源任务、内容 sha256、缩略图。
- 查重：先按 `dedupeKey` 查可用版本（复用）；再查 pending 请求（关联等待）；都没有才新建 pending + 任务。并发同一键只会建一个。
- 版本：新生成结果产生新版本（version+1，parentAssetId 指向旧版），旧版本保留可查；已排版内容固定引用具体版本（A 端回填记录 assetId+sha256，不随公共资产更新自动改变）。
- 同步：A 端协作页只拉元数据与缩略图（`/thumb`），原图在「下载/使用」时按需拉取缓存并登记本地 asset；不做全量原图复制。
- 生成结果入库：任务 done 时中控同一事务写资产 available、请求 done、发 `asset.created` 通知。

## 10. 通知

事件：任务完成/失败/待核实/冲突/迟到结果、资产入库、节点上线/离线/被吊销、配对请求。
中控维护递增 `seq`；客户端按 `since` 增量拉取；节点心跳响应带增量通知。控制台 2s 轮询。
A 端还写本地通知（回填成功/冲突），协作页合并展示。

## 11. 安全（局域网）

- 默认绑 `0.0.0.0:18897`，但所有 `/api/*`（health/pair 除外）必须带 token；token 存 sha256，可吊销。
- 设备配对：中控启动生成 6 位配对码（终端打印 + `配对码.txt`），节点/客户端凭码换 token；支持轮换、吊销。
- 节点只接受白名单任务类型与 `allowedProjectIds`；只回调固定本机地址；**不实现任何命令执行/文件浏览接口**。
- 上传限 64MB/图、请求体限 4MB（任务 JSON）；URL 路径白名单。
- 中控控制台静态文件白名单；日志脱敏 token。

## 12. 验证（必须真实执行，见 `tests/` 与 README「验证结果」）

自动化（本机单机模拟多进程，全部不调用真实生图/账号/外网）：
1. 两节点争抢同一任务：恰好一个领到，另一个空手。
2. 同一资产并发申请：只产生一个 pending 资产 + 一个任务；两个申请者都得到 join/reuse。
3. 节点掉线：租约过期 → `claimed` 回队可重派；`generating` → `verifying` 不重派。
4. 中控重启：任务/节点/资产/apply 状态恢复，未完成任务可继续。
5. 上传失败：节点重传；重复回传幂等；旧尝试迟到结果只登记不覆盖。
6. 重复提交：同幂等键不重复建任务；重复回填只回填一次。
7. 回填目标已被修改：协作结果保留为候选、不覆盖新编辑，`apply=conflict`。
8. 执行适配层：fake bridge 下真实走 `pump()`/名额/job 目录，断言真实桥被调用且结果文件被校验；绝不真实联网生图。
9. 现有回归：`panel-generation.test.mjs`、`page-generation.test.mjs`、`jobs-cancel-all.test.mjs` 全绿。

无法在本机完成的：真实第二台电脑、真实 Codex 账号生图。必须在 README 明确写「未验证」并给真机验收步骤。
