# 漫画共享资产中心

源码和默认数据均位于本目录。Node.js 24 或更新版本；图片解码使用现有 `@napi-rs/canvas`。不安装运行库，不读取生图账号凭据。`sdk/adapter.example.mjs` 尚未接入任何小伙伴的真实生图工具。

## 本机使用

从新版工作台的 `启动AI设计版.cmd` 启动。启动器会发现相邻目录或原 D 盘位置的共享资产中心，启动 `http://127.0.0.1:19080/`，并在首次使用时把专用 client / worker 令牌写入工作台自己的 `runtime-data/main/asset-center.local.json`，不会把令牌返回界面。已有连接配置保留。生图接单器默认停止，只有用户点击并确认生图时才启动，只领取该次提交的本话任务。

工作台中打开“资产库 → 导入资产与本话匹配”：选择左侧缺图项后点击“生成当前缺失资产”，或者“批量生成本话缺失资产”。任务区显示服务器记录的排队时间、生成耗时、最近心跳、回传和待确认状态。生图无可靠百分比时只显示状态和消息。候选图不会自动替换正式资产；看图后点击“采用并匹配对应画格”。同步只补当前话缺少的绑定，保留已有固定版本、手动参考、锁定项、画布图片、提示词和取景。

资产中心网页用于集中管理。首次管理员令牌仅在 `data/首次连接凭据.local.json` 中，使用“接入管理”创建作品专用的工作台和接单器令牌。普通工作台令牌可以对自身作品的候选图执行人工审核，无需管理员令牌。管理员令牌不配置给工作台。

## 外部工具与手动交付

1. 工作台选择“外部工具 / 手动交付”，提交本话需求，或导出 Excel / JSON 给制作人员。
2. 制作人员完成图片后，在工作台任务区点击“手动上传交付图片”；上传后仍需看图确认。也可在资产中心管理员页面上传。
3. 需要自动接单时，将 `sdk/worker.example.json` 复制成 `worker.local.json`，填入单独发放的作品专用 worker 令牌、workId 和现有工具的 adapter 路径。运行 `node sdk/run-worker.mjs worker.local.json`。
4. adapter 导出 `async generate({task,references,directory,signal,onProgress})`。使用 `task.brief.prompt/spec/style/usages` 和固定参考图版本；结果返回 `{filePath: 生成图片的绝对路径}`。只在能证明生成已结束时给错误标记 `generationEnded=true`；无法证明时交给人工核实。

SDK 自动领取、定期心跳、校验参考图、保存交付日志、回传图片，断网后保留待上传原图。重启先恢复上传，不会重新生成。失联、执行状态不明的旧任务会阻止接新任务；核实原任务已结束后，人工重试。任务的幂等键不能复用到不同内容；同一资产存在活动任务时不会再创建第二个。人工“重新生成候选版本”保留旧正式版，工作台已有引用不会自动漂移。

接口协议见 `public/openapi.json`；SDK 只提供接口适配，尚未完成任何外部生图工具的真实联调。

## 局域网部署

在中心电脑设置 `ASSET_CENTER_DATA=D:\共享资产数据`，运行 `node server.mjs --lan`。默认端口19080；`ASSET_CENTER_PORT` 可更改。只向可信局域网放行中心端口。所有 `/api/v1/*` 接口必须携带 `Authorization: Bearer <令牌>`。按作品发令牌可隔离作品；撤销后立即失效。自定义内网域名用 `ASSET_CENTER_ALLOWED_HOSTS`（逗号分隔）配置。

其他电脑工作台仍只监听127.0.0.1，在资产窗口的高级连接设置中一次填写中心内网地址和分配的令牌。只有负责本机Codex接单或手动交付的电脑需要 worker 令牌。无需复制图片，采用时自动缓存固定版本，缺失缓存时自动从中心恢复，并验证SHA-256。勿把无认证的本地工作台转发到公网。

## 备份与迁移专用电脑

1. 停止各工作台接新任务，等待正在生成/回传的任务完成。失联任务先核实原任务；迁移不重派。
2. 中心运行时执行 `node tools/backup.mjs`，得到一致的 SQLite 数据库与图片备份（`data/backups/时间戳`）。停止中心：`node tools/stop-center.mjs`。
3. 将中心源码、完整 `data` 目录复制到新电脑 D 盘，保持数据库、blobs、首次连接凭据和实例ID一起迁移。不要只复制 SQLite 主文件而遗漏正在使用的 WAL；应停机后复制完整数据，或使用上一步备份。备份恢复时把该备份的 `center.sqlite` 和 `blobs` 放入新的数据目录，原本分配的令牌继续有效；首次凭据另行妥善迁移。
4. 配置现有 Node 24 和 canvas 路径（`ASSET_CENTER_CANVAS_MODULE`），运行 `node server.mjs --lan`。工作台改为新的内网地址，保存令牌不变。相同实例ID和版本ID保证旧工程引用、取景与缓存仍然有效。
5. 已发给小伙伴的发布包只含源码、SDK、说明和合成验收截图，不含 `data`、`.local.*`、真实工程、任务日志或令牌。迁移数据请单独传送，不能混入公开发布包。

## 验证范围

合成资料与假生图通道已验证领取、心跳、失联不重派、迟到结果、审核、资产版本、固定缓存恢复、单项/批量、话数隔离、人工交付和 Playwright 界面操作。真实 Codex 路径复用工作台原有 `CodexBridge.generate`；本次不调用真实AI、不登录、不检查账号凭据。真实生图质量及其他小伙伴工具需后续各自授权后联调。
